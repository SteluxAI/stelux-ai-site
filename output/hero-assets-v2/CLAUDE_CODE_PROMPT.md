## 3. 素材接入与构图

把选用的生产图片复制到 `public/img/hero-v2/`，保留交接目录的源文件。优先使用经验证保留 alpha 的 WebP，PNG 可作为回退；不要将透明图转换成无透明通道的格式。不要给透明区域填背景，也不要叠加深色 filter、整体低透明度或重模糊来压暗素材。先通过位置、尺寸和现有天空颜色实现协调。

山丘和前景各使用一个 `<picture>`，两者都在 `max-width: 767px` 选择手机专用构图，`min-width: 768px` 选择桌面图。不要只更换山丘而继续放大桌面前景。根据实际尺寸设置正确的固有宽高，必要时给不同媒体源设置尺寸或响应式 aspect-ratio，避免布局跳动。保留 `.hills` 和 `.hero-fg img` 等现有依赖选择器，或同步更新所有引用。

分层关系保持为：代码天空 → 山丘 → 真实内容与仪表盘 → 透明前景。装饰层使用 `aria-hidden="true"`、图片 `alt=""`，且不接收鼠标事件。前景应遮住仪表盘底边的少量区域以产生纵深，左右两翼可以较高，中央冠层必须低于重要内容。首次进入与正常滚动过程中，标题、两个主要 CTA、仪表盘身份信息和 Open workspace 按钮都应清楚可读；仅设置 `pointer-events:none` 不能解决视觉遮挡。

不要直接沿用旧 `--crest`、`--hills-h`、`--fol-h` 或 `width:170% / 230%`。移除旧手机硬裁切，并重新评估平板的 `150%` 前景放大。依据新图的真实透明留白、山脊高度和渲染宽度设置定位：像素偏移的基本关系是“源图内边界 y / 源图宽 × 实际渲染宽”。山丘的天空留白不等于可见地形高度，不能只靠整张图片比例猜测地平线。

当前 `horizon()` 会把 `--crest` 的数值当作 `vw` 换算，并与 `.hills-wrap.offsetTop` 相加。若改变量名、单位或定位方式，必须同步更新该计算，保证 Canvas 暮色亮带仍落在山脊附近。保留 `#aurora`，不要让无空值保护的 `initSky()` 失效。天空顶部保持足够深，以支撑白色标题；不要整体把景观罩灰。

## 4. 滚动、接缝与加载

保留现有 GSAP/Lenis 视差和桌面仪表盘轻微倾斜效果，并按新构图校准位移幅度与背景覆盖范围。前景、山丘的图片底部及其补色层必须在视差全程连续，不能出现矩形边界、透明露空或明显色块。现有 `.hills-wrap::after` 的 `#0f140c`、`.hero-fg::after` 的 `#0a0908` 是按旧图设置的，应匹配新图实际底色或改用足够的素材延伸，不能盲目保留。还要检查 Hero 与下一段 Products 的衔接。
